THE PROBLEM
CONTEXT

「人在环中」保证了安全，却常常变成纯粹的负担

01
你并不关心执行细节
要不要跑 bash、装哪个依赖、选 A 还是 B —— 这些是实现层面的琐事，你只想要最终结果，不想被每步打断。
02
你不清楚该怎么决策
agent 抛来很专业的选择题（用哪种缓存策略？这个报错要不要忽略？），你并不比它掌握更多信息，硬要拍板反而是瞎猜。
03
大多数时候「推荐选项」就够了
agent 的建议八成是对的，你每次只是机械地点「同意」—— 这种确认没产生任何决策价值。
04
你在离开屏幕
想让流程在你开会、睡觉时继续推进，而不是卡在一个简单弹窗上干等几个小时。
这一步确实需要一个判断，但那个判断不非得是「你本人」来做 —— 你要的是一个足够可信、又不用你亲自到场的决策来源。

THE SOLUTION
HOW IT WORKS

把请求丢给你之前，先问一圈其他 agent

1
投票 agentvoters
以一次性、禁用所有工具的方式，仅凭最近上下文投出 allow / deny（或选出选项）并附上理由。
2
裁决者decider
由会话自己的 agent 担任，把大家的意见汇总成一句话摘要，作为这一票的最终陈述。
3
决议 / 回落decide or defer
达成共识 → 自动决议、无需你出面；达不成 → 回落到你，并把每票和理由一并展示，帮你更快决策。
同一套投票 agent、同一条回落到人的底线，覆盖三类决策：工具权限 allow/deny ｜ AskUserQuestion 逐题作答 ｜ 自动化编排的检查点（继续 还是 等待人工）。

0307
THE GUARDRAILS
SAFETY

理解这三条，你才敢放心开

01
永远可回落到人
任何投票出错、超时、无法解析，都记为弃权；弃权就不算一致，这道题重新交回你手上。绝不替你冒险拍板。
02
至少要有一个「别人」
如果除会话自己外没有其他 agent 可投票，共识会被跳过，照常问你 —— 不存在自己给自己放行。
03
自动决策留痕可追溯
每一次无人参与的自动决议，都在工作台（WorkCenter）的「自动」筛选下留一条仅审计、不阻塞的记录，事后可查。
共识只会帮你省掉「能确定的那部分」，一旦有真正的分歧，方向盘永远还在你手上。
SAFETY

IN c3
SETTINGS

三个开关逐层收窄：开不开 → 怎么算通过 → 谁来投

开关
关闭 · 默认
打开 · 更自动
01启用共识投票
照旧问你每个敏感调用、每道选择题都直接问你。
先投票全体一致才自动决议，否则仍交给你（附各 agent 意见）。
02允许多数决
仅全体一致任何分歧、弃权都回落到你。
严格多数即决议弃权不计票；但平票 / 无明显多数 / 全体弃权仍交你决定。
03谁来投票
全部 agent除会话自己外，每个已启用 agent 都参与。
自定义只挑允许投票的子集，仅做缩小；清单为空则跳过共识。
投票始终限于会话自身 vendor 的已启用 agent，不同 vendor 永不互投。多数决还会顺带启用检查点共识：开发循环卡住、或有未答选择题时，同一批 agent 投票决定流程 继续 还是 等待人工。

ROLLOUT
HOW TO START

从最保守起步，按需逐层放开

1
先只开总开关
全体一致
感受哪些原本要你点确认的操作，现在被「全票通过」自动放行 —— 零风险的自动化红利。有任何分歧，决定权仍在你手里。
→
需要更快时
叠加多数决
当总有一两个 agent 因口味不同拖住全票、而多数意见其实很清晰时，用多数决换更高自动化率；平票和无明显多数仍回到你，底线不丢。
→
用「自定义」
精修投票团
若圆桌里有只读或不专业的 agent 在稀释票池，切到自定义，只保留你信得过的几个 agent。
节奏的关键：先尝零风险红利，再按需换自动化率 —— 每一步放开，都不动摇「有分歧就回落到人」这条底线。
