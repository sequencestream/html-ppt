## 第 01 页 · 封面 / 钩子

- **Tagline**：c3 GUIDE / MULTI-AGENT CONSENSUS
- **主标题**：
  - 多Agent
  - **共识投票**（橙色强调）
- **脚注**：c3 是一个多 agent 的圆桌。默认每一次有副作用的工具调用、每一道选择题都要**暂停下来问你**。多智能体共识让**其他 agent 先表决**——能自动定的就自动定，定不了才叫你。
- **右侧视觉锚点**：一张「投票圆桌」——多个智能体席位各自举出 allow / deny 的票，中心是一个被解放出来的人。
- **页脚**：c3 GUIDE · CONSENSUS ｜ 01 · 07

**讲解要点**：开场点题——把你从「每一步都要点确认」里解放出来。核心比喻：既然圆桌上还坐着其他 agent，为什么不让它们先投票？

## 第 02 页 · 背景 · 人在环中的四种负担

- **Topbar**：THE PROBLEM ｜ 徽标 CONTEXT
- **标题**：「人在环中」保证了安全，却常常变成纯粹的负担
- **副文**：默认情况下，agent 每动一次有副作用的工具（写文件、跑命令、发 PR），权限网关就**暂停问你** allow/deny；agent 抛出 `AskUserQuestion` 时也要**等你亲自作答**。这在很多场景里是负担：
- **四负担（卡片 / stat grid）**：

  | # | 负担 | 说明 |
  |---|------|------|
  | 1 | 你并不关心执行细节 | 要不要跑 `bash`、装哪个依赖、选 A 还是 B——这些是实现层面的琐事，你只想要最终结果，不想被每步打断。 |
  | 2 | 你不清楚该怎么决策 | agent 抛来很专业的选择题（用哪种缓存策略？这个报错要不要忽略？），你并不比它掌握更多信息，硬要拍板反而是瞎猜。 |
  | 3 | 大多数时候「推荐选项」就够了 | agent 的建议八成是对的，你每次只是机械地点「同意」——这种确认没产生任何决策价值。 |
  | 4 | 你在离开屏幕 | 想让流程在你开会、睡觉时继续推进，而不是卡在一个简单弹窗上干等几个小时。 |

- **金句条**：
  > 这一步确实需要一个判断，但那个判断**不非得是「你本人」来做**。你要的是一个「足够可信、又不用你亲自到场」的决策来源。
- **页脚**：CONTEXT ｜ 02 · 07

**讲解要点**：四种场景的共同点，正是「需要判断，但不必是你」。这句话直接引出下一页的方案。

## 第 03 页 · 方案 · 让多个 agent 先投票

- **Topbar**：THE SOLUTION ｜ 徽标 HOW IT WORKS
- **标题**：把请求丢给你之前，先问一圈**其他** agent
- **副文**：核心逻辑很简单——这次工具调用该不该放行？这道选择题该选哪个？先让圆桌上的其他 agent 表决。
- **三步机制（编号条 / 横向流程）**：

  | # | 角色 | 做什么 |
  |---|------|--------|
  | 1 | 投票 agent | 以一次性、**禁用所有工具**的方式，仅凭最近上下文投出 allow/deny（或选出选项）并附上理由。 |
  | 2 | Decider 裁决者 | 由会话自己的 agent 担任，把大家的意见**汇总成一句话摘要**。 |
  | 3 | 决议 / 回落 | 达成共识 → **自动决议、无需你出面**；达不成共识 → 回落到你，并把每票和理由一并展示，帮你更快决策。 |

- **覆盖范围条（右侧 / 底部）**：
  > 同一套投票 agent、同一条回落到人的底线，覆盖三类决策：
  > **工具权限** allow/deny ｜ `AskUserQuestion` **逐题作答** ｜ 自动化编排的**检查点**（`继续` 还是 `等待`人工）。
- **页脚**：HOW IT WORKS ｜ 03 · 07

**讲解要点**：三步是「投票 → 汇总 → 决议或回落」。强调投票 agent 禁用一切工具，只做纯判断；覆盖范围远不止权限弹窗。

## 第 04 页 · 底线 · 三条刻在骨子里的安全承诺

- **Topbar**：THE GUARDRAILS ｜ 徽标 SAFETY
- **标题**：理解这三条，你才敢放心开
- **三底线（卡片）**：

  | # | 底线 | 内容 |
  |---|------|------|
  | 1 | 永远可回落到人 | 任何投票出错、超时、无法解析，都记为**弃权**；弃权就不算一致，这道题重新交回你手上。共识只帮你省掉能确定的那部分，**绝不替你冒险拍板**。 |
  | 2 | 至少要有一个「别人」 | 如果除会话自己外没有其他 agent 可投票，共识会被**跳过**，照常问你。 |
  | 3 | 自动决策留痕可追溯 | 每一次无人参与的自动决议，都会在工作台（WorkCenter）的「自动」筛选下留下一条**仅审计、不阻塞**的记录——事后可查是谁、何时、依据什么放行。 |

- **金句条**：
  > 共识只会「帮你省掉能确定的那部分」，**一旦有真正的分歧，方向盘永远还在你手上**。
- **页脚**：SAFETY ｜ 04 · 07

**讲解要点**：这三条是「敢开」的前提。核心是弃权即回落——出错、超时、无人可投，全部安全地退回人工，绝不弄险。

## 第 05 页 · 配置 · 三个开关逐层收窄

- **Topbar**：IN c3 ｜ 徽标 SETTINGS
- **标题**：从「开不开」到「怎么算通过」再到「谁来投」
- **说明**：在工作区（Workspace）的 Consensus 区块里，三个开关逐层收窄。
- **三开关（编号条）**：

  | # | 开关 | 关闭（默认） | 打开 |
  |---|------|------|------|
  | 1 | **启用多智能体共识投票** | 一切照旧，每个敏感调用、每道选择题都直接问你。 | 先投票；**全体一致**才自动决议，否则仍交给你（附带各 agent 意见）。 |
  | 2 | **允许多数决** | 仅**全体一致**：每个投票者结果相同才决议，任何分歧/弃权都回落到你。 | 弃权不计票，**严格多数**即可决议；但**平票 / 无明显多数 / 全体弃权**仍交由你决定。 |
  | 3 | **谁来投票** | 全部 agent（默认）：除会话自己外每个已启用 agent 都参与。 | 自定义：从已启用清单里挑**允许投票的子集**，只做「缩小」；清单为空则跳过共识。 |

- **提示条（底部）**：
  > 多数决还会顺带启用**检查点共识**：开发循环卡住、或有未答选择题时，同一批 agent 投票决定流程 `继续` 还是 `等待`人工。c3 会诚实区分「所有 agent 一致…」与「多数派裁决…」，让你一眼看出这一票怎么来的。
- **页脚**：SETTINGS ｜ 05 · 07

**讲解要点**：三个开关是漏斗——总开关决定开不开，多数决决定通过门槛，谁来投决定票池。投票**始终限于会话自身 vendor 的已启用 agent，不同 vendor 永不互投**；自定义只在该集合内进一步收窄，且被双重过滤，失效 id 不可能复活成投票者。

## 第 06 页 · 节奏 · 建议的开启顺序

- **Topbar**：ROLLOUT ｜ 徽标 HOW TO START
- **标题**：从最保守起步，按需逐层放开
- **三步节奏（横向流水线 / 编号条）**：

  | 步骤 | 动作 | 收益与底线 |
  |------|------|-----------|
  | 1 | **先只开总开关（全体一致）** | 感受哪些原本要你点确认的操作，现在被「全票通过」自动放行——**零风险的自动化红利**。只要投票者有任何分歧，最终决定权仍在你手里。 |
  | 2 | **需要更快时叠加多数决** | 当总有一两个 agent 因口味不同拖住全票、而多数意见其实很清晰时，打开多数决换取更高自动化率；平票和无明显多数仍回到你，**底线不丢**。 |
  | 3 | **用「自定义」精修投票团** | 若圆桌里有只读或不专业的 agent 在稀释票池，切到自定义，只保留你信得过的几个 agent。 |

- **页脚**：HOW TO START ｜ 06 · 07

**讲解要点**：节奏的关键是「先尝零风险红利，再按需换自动化率」。每一步放开都不动摇「有分歧就回落到人」这条底线。
