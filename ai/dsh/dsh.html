DEEPSEEK HARNESS  /  TECHNICAL ANALYSIS
DeepSeek Harness
从 Coding Agent 到可组合 Agent Runtime
它的目标不是只做一个对标 Claude Code 或 Codex 的 Coding Agent，而是以 Coding Agent 为首个应用，向下抽象出一个可动态重组的 Agent Runtime。
关键问题：运行中换件后，副作用、依赖与会话是否仍然一致、可恢复、可回放？

HARNESS ENGINEERING

  • 组装 system prompt、历史消息、Skills 与工具 schema

0415
核心难题
SAFE RECOMPOSITION

真正困难的不是「加载插件」，而是安全地换件

01 / Teardown
副作用能否撤销？
监听器、工具注册、timer 与资源句柄必须完整回收。
02 / Dependency
依赖变化如何传导？
provider 消失或更换时，下游应自动停用、重载并恢复。
03 / Async
旧结果会否覆盖新状态？
初始化期间配置变化，需要明确的取消与版本语义。
04 / Continuity
能否不重启进程？
频繁变化时仍要保留 process-local state 与会话连续性。
时间可组合性
Revertible Effects
组件移除后，对共享环境造成的修改可以完整、安全地撤销。
空间可组合性
Reactive Coeffects
组件声明依赖，Runtime 响应 provider 的出现、消失与替换。
动态重组 = 副作用回收 + 依赖协调 + 状态一致性，而不是一次「热加载」。

0515
Cordis 原理一
REVERTIBLE EFFECTS

副作用必须携带逆操作

ctx.effect(callback)
ctx.effect(() => { const timer = setInterval(refresh, 1000) return () => clearInterval(timer) })
创建注册副作用
→
记录保存 disposer
→
卸载LIFO 回收
Design Benefit
创建与撤销局部共置
降低遗漏；父插件 teardown 可级联回收子插件资源，并为 HMR 与运行中换件提供恢复语义。
Guarantee Boundary
可追踪不等于正确回滚
Runtime 只能调用 disposer，不能证明它恢复原状态；绕过 Context 的外部写入不会自动回滚。
Engineering Requirement
外部副作用仍需独立控制
数据库与文件写入仍要依赖事务、幂等、补偿操作和独立审计。
REVERTIBLE EFFECTS
0615
Cordis 原理二
REACTIVE COEFFECTS

依赖变化，直接驱动组件生命周期

依赖齐备

consumer 自动激活，不依赖人工编排启动顺序。

provider 消失

consumer 停用，停止消费失效服务。

provider 替换

consumer 重载并重新绑定新实现。

provider 卸载

先停止服务，再等待下游 teardown，最后回收自身。

普通 DI 通常在启动时解析一次；
Reactive Coeffects 把依赖解析变成持续的运行时过程。
Unified Context
一套原语覆盖依赖、作用域与状态
set/get 服务 ｜ effect/on 副作用 ｜ isolate realm ｜ intercept 策略元数据 ｜ Fiber 状态机
插件不再是静态安装包，而是带依赖、作用域、状态机和可逆副作用的运行时组件。

Execution Units
Step 与 Turn 分工
Step 是一次模型请求及其工具调用；Turn 是一次用户输入触发的完整处理，可包含多个 Step。
Why It Matters
长任务可以被安全介入
UI 消息、后台结果和系统 Context 不再竞争同一模糊队列；claim、discard、splice 均有事件语义。

工具系统
POLICY PIPELINE

工具执行不是一次函数调用，而是一条受控策略管线

pre-execute策略入口
→
monotonic guard权限只收紧
→
execute工具实现
→
post-execute转换与审计
→
finalizeimmutable result
Insertable Policies
工具与策略解耦
allow / deny / ask、sandbox、timeout、输出裁剪、审计和结果转换，可按 Profile 独立叠加。
Deterministic Concurrency
默认独占，显式并发
只有声明 isConcurrencySafe 的调用进入有界并发池；调用顺序与结果写入顺序保持一致。
Capability Control
逻辑权限 ≠ 进程隔离
Context capability control 管理可信组件间的逻辑权限，但不能隔离恶意进程内代码。
Security Boundary
不可信代码必须移出进程
使用 container、microVM、WASM 或外部 sandbox 建立真正的资源隔离。
默认保守、显式证明安全、结果顺序稳定，降低并行执行造成的上下文不确定性。

Agent Runtime
独立度量Harness 将拥有独立版本、benchmark、成本与安全指标。
